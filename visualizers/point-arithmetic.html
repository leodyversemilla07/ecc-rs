Elliptic curve operations

Pick a prime p, the curve y² ≡ x³ + ax + b (mod p), and two points. Every step is computed the way EllipticCurve computes it — including the branches where add or double refuses the input and panics.

the formulasthe curve and the group law

A point on the curve over Fp satisfies the curve equation. The group law turns two points into a third one, and the crate splits it into the slope and the two resulting coordinates.

the curve

y²≡x³ + ax + b (mod p)

EllipticCurve::on_curve — the test that decides whether a coordinate is a point of the curve. It returns false for the identity, which is not an affine coordinate.

the slope of the chord

s≡(y₂ − y₁) · (x₂ − x₁)⁻¹ (mod p)

The slope of the line through two distinct points. The inverse is Fermat's little theorem, so this is one modular exponentiation — see the finite field page.

the result

x₃=s² − x₁ − x₂
y₃=s(x₁ − x₃) − y₁

compute_x3_y3 — shared by addition and doubling. The third intersection of the line with the curve, reflected across the x-axis.

the slope of the tangent

s≡(3x₁² + a) · (2y₁)⁻¹ (mod p)

EllipticCurve::double — the tangent instead of the chord. The result uses the same formulas with x₂ = x₁, so x₃ = s² − 2x₁.

the reflection

P + (−P)=O

The exceptional case of the chord: when x₁ == x₂ and y₁ + y₂ ≡ 0, the line is vertical and the sum is the identity. The crate returns Point::Identity here.

scalar multiplication

d · P=double-and-add over the bits of d

EllipticCurve::multiply — for each bit, from the most significant down: double the accumulator, then add the base point once more if the bit is 1.

the double-and-add ladder

EllipticCurve::multiply processes the scalar from the most significant bit down. For each bit it doubles the running value t, and when the bit is 1 it adds the base point once more. The dashed path on the grid is that ladder.

This page mirrors what is in ecc/src/elliptic_curve.rs and ecc/src/point.rs. It does not add any theorem or curve fact that is not in those files. It shows:

  • on_curve: y² ≡ x³ + ax + b (mod p) — and false for the identity.
  • add: the two identity arms, the two on_curve asserts, the x1 == x2 && y1 + y2 ≡ 0 branch, then assert!(c != d), then the slope and the x₃ / y₃ formulas.
  • double: the identity arm, the on_curve assert, the y1 == 0 branch, then the doubling slope.
  • compute_x3_y3: the shared x₃ = s² − x₁ − x₂, y₃ = s(x₁ − x₃) − y₁.
  • multiply: the double-and-add loop, bit by bit.
  • FiniteField: add, sub via p − c, mul, divide, and inverse_mul as c^(p−2) mod p.
The ℝ panel is a separate geometric drawing aid, not part of the Fp computation.
notes

add() needs two different points

add checks the reflection branch first and only then asserts that the two points differ. Adding a point to itself with y ≠ 0 panics — use double instead.

the reflection branch wins

Because the vertical-line test runs before the assertion, P + (−P) returns the identity cleanly, and P + P with y = 0 also returns the identity — that is the assignment case.

identity is handled first

After the match, add returns the other point when either input is Point::Identity. Two identities are equal, so add(∞, ∞) still hits the assertion.

same-x or inverse branch

For two coordinate points the code returns Point::Identity when x1 == x2 or y1 + y2 ≡ 0 (mod p). Both tests are shown side by side.

on_curve says no to the identity

on_curve returns false for Point::Identity — it is not an affine coordinate. That is why the identity is matched before the assert.

the slope is a division

Every slope is numerator × denominator^(p−2) mod p, the Fermat's little theorem inverse from FiniteField. The finite field page walks through that.
