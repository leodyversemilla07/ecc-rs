ECDSA

The Elliptic Curve Digital Signature Algorithm, built on the ecc library. Three stages — key generation, signing, verification — each computed exactly the way Ecdsa in the ecdsa crate computes it.

the three stages

1 · key generation

Q = d·G

Alice picks a private key d with 1 ≤ d ≤ n−1 and computes the public key Q = dG. Anyone can compute Q; nobody can recover d — that is the discrete logarithm problem.

2 · signing

r = x(kG) mod n
s = k⁻¹(H(M) + r·d) mod n

A fresh random nonce k gives the random point R = kG; its x-coordinate becomes r. The signature is the pair (r, s).

3 · verification

P = u₁G + u₂Q
x(P) ≡ r (mod n)

The verifier rebuilds a point from public data only and compares its x-coordinate with r.

why verification worksthe proof from lesson 29
  1. We know from the signing step that s = k⁻¹(H(M) + r d) mod n.
  2. In verification we do not know d or k — only s, r, H(M) and Q.
  3. Multiply both sides by k: k s = H(M) + r d mod n.
  4. Multiply by s⁻¹: k = s⁻¹ H(M) + s⁻¹ r d mod n.
  5. Using the definitions of u₁ and u₂: k = u₁ + u₂ d mod n.
  6. Multiply both sides by the generator G: kG = u₁G + u₂ dG.
  7. Since Q = dG, this becomes kG = u₁G + u₂Q.
  8. The left side is R = kG. The right side is P = u₁G + u₂Q. Therefore P = R.
  9. Both points are the same, so their x-coordinates are the same: x(P) = x(R) ≡ r (mod n).

We only compare the x-coordinate because r is derived from the x-coordinate of R. The signature does not carry y(R), and it does not need to.

the nonce must never repeat

Sign two messages M₁ and M₂ with the same k and the same private key d, and r is the same for both. Subtracting the two signing equations gives:

s₁ − s₂ = k⁻¹(H₁ − H₂)⇒k = (H₁ − H₂)·(s₁ − s₂)⁻¹

and then d = r⁻¹(s₁ k − H₁) mod n — the private key is gone. This is how the PlayStation 3 was broken in 2010.

the scalar multiplicationseach is a double-and-add ladder

Key generation, signing and verification all reduce to EllipticCurve::multiply. Each row is one bit of the scalar: t = double(t), and t = add(t, G) when the bit is 1.

notes

sign() takes the nonce from the caller

Ecdsa::sign does not generate k. Standard ECDSA requires a fresh nonce whenever r = 0 or s = 0; the CLI in ecdsa/src/main.rs retries in a loop.

the order must be prime

FiniteField::inverse_mul uses Fermat's little theorem, so the group order n has to be prime. The teaching curve uses 19.

the hash is reduced, not truncated

generate_hash_less_than takes the SHA-256 digest modulo n − 1 and adds one, so the hash always lands in 1 … n−1.

verification is not free

Verifying needs two scalar multiplications — u₁G and u₂Q. For secp256k1 that is the dominant cost of a signature check.

a small curve can make verify panic

Ecdsa::verify calls EllipticCurve::add, which asserts the two points differ. On a curve with 19 points u₁·G and u₂·Q sometimes land on the same point. Press random k a few times to see it.

the hash is computed here

SHA-256 is implemented in plain JavaScript in visualizers/assets/ecc.js, so the page works offline and over file:// without the Web Crypto API.
