Finite field operations

In a field with p elements the numbers sit on a clock with the hours 0 … p−1. Every operation is a walk around that clock. This page mirrors FiniteField from the ecc crate: each step is the line of Rust it comes from, and each result is the value the Rust code returns.

the formulasthe six operations, side by side

The field is Fp = {0, 1, …, p−1} with every operation taken modulo p. These are the six functions in FiniteField, each with the crate function that implements it — plus the theorem that makes the two inverses work.

addition

a + b≡(a + b) mod p

FiniteField::add — the one primitive. Both operands must already be reduced (a < p); the function asserts it.

subtraction

c − d≡c + (p − d) mod p

FiniteField::sub — not a primitive. It adds the additive inverse of d, and so it reduces d itself.

multiplication

a × b≡(a · b) mod p

FiniteField::mul — the second primitive. Same precondition as add: both operands must already be reduced.

additive inverse

−c≡(p − c) mod p

FiniteField::inverse_add — one subtraction, no exponentiation. Note that −0 ≡ 0, which is why the crate reduces the result once more.

multiplicative inverse

c⁻¹≡cp−2 mod p

FiniteField::inverse_mul — one modpow, using Fermat's little theorem. Requires a prime p and a non-zero c; the crate does not check either.

division

c ÷ d≡c · dp−2 mod p

FiniteField::div — not a primitive. It multiplies by the multiplicative inverse, so it inherits the prime-modulus assumption.

fermat's little theorem

ap−1≡1 (mod p)

The theorem behind both inverses: for a prime p and any non-zero a, ap−1 ≡ 1. Dividing by one a gives ap−2 ≡ a⁻¹, which is exactly what inverse_mul computes. The live panel below walks it step by step.

and the consequence

ap−1≡1⇒ap−2≡a⁻¹

This is the whole reason inverse_mul is one modpow instead of a search for b⁻¹ by trial — and the reason the crate insists on a prime modulus. The fermat's little theorem panel below walks the chain.

Only add and mul do arithmetic. Everything else is built from them, which is why the crate has exactly two primitive operations.

flt-powered divisionwhat FiniteField::div does
Why it works. By FLT, b^(p−1) ≡ 1 (mod p). Split off one b: b × b^(p−2) ≡ 1. So b^(p−2) is by definition b⁻¹, and a ÷ b = a × b^(p−2) mod p.

power chain

flt vs. brute force

modulo for big numbersBigUint arithmetic
The crate stores every field element as a num_bigint::BigUint, so the same arithmetic works for a toy curve and for 256-bit secp256k1. Two facts keep huge numbers tractable: N = q × m + r gives N mod m, and modpow never builds a^e — it squares and multiplies.

method 1 — bring the digits down one at a time

Reducing mod m after every step gives the same remainder, because (x mod m) × 10 + d ≡ x × 10 + d (mod m). Only one small running remainder r is ever written down — exactly like long division on paper.

method 2 — huge powers, square and multiply

why p must be primethe crate assumes it

FiniteField::inverse_mul assumes that p is prime — it uses Fermat's little theorem, which only holds for a prime modulus. The crate documents this as a known limitation: the function does not verify primality.

notes

wrapping is the whole idea

"mod p" means: when you pass p−1, go back to 0 and keep counting. That is why results never leave the clock.

two kinds of inverse

The additive inverse −a satisfies a + (−a) ≡ 0 and is p − a. The multiplicative inverse a⁻¹ satisfies a × a⁻¹ ≡ 1 and is a^(p−2).

only two real operations

Subtraction is adding −b and division is multiplying by b⁻¹, so add and mul are the only two primitives in the crate.

the asserts are load-bearing

FiniteField::add and mul assert that both operands are already reduced. The crate never reduces an input for you.

flt gives inverses for free

Instead of searching for b⁻¹ by trial, Fermat says b⁻¹ = b^(p−2) mod p. This is how real crypto libraries compute modular inverses in prime fields.

flt ≠ primality proof

FLT can only disprove primality. Passing for all bases is necessary but not sufficient — Carmichael numbers are the counterexamples.
